# Plan 4: CLI (Stricli)

**Goal:** The `diff-digest` command, built with Stricli, on top of the lib (plans 1–2) and the contract and server (plan 3). Each command validates its input, validates its output against a zod schema before it prints, and maps errors to the spec §6 exit codes.

**Spec:** `docs/superpowers/specs/2026-09-30-typescript-rewrite-design.md` §5.2 (digest reference), §6 (errors and `--json`), §8 (CLI). Carry-forward tables at the end of the plan 1–3 files.

**Execution:** the controller builds each task in the repo with `bun run verify` passing before each commit, then an Opus whole-plan review, one fix wave, and a re-review (user goal 2026-10-01).

## Global constraints

- Same as plans 1–3 (strict TypeScript and lint, no suppressions, no `as` except `as const`, `XSchema`, readonly, `u` regexes, file and function size limits, conventional commits with no co-author line, `main`, do not edit `bin/`, `ui/`, `scripts/install.mjs`).
- New exact dependencies: `@stricli/core` 1.3.0; `@orpc/openapi` and `@orpc/zod` 1.15.4 (for `schema --openapi`).
- `--json` on every command that prints data: `{ ok: true, data }` or `{ ok: false, error: { code, message, hint?, data? } }`. Exit code 0, or `EXIT_CODES[code]`. A usage error (unknown command, bad flag, bad argument) exits with 2.
- Docs and prompts are imported as text (`with { type: "text" }`), so the plan 7 binary contains them.

## Rulings in this plan

| Ruling | Why |
|---|---|
| Commands are plain Stricli `buildCommand` calls. One helper, `emit(context, options, run)`, does the output: it validates `run()`'s result against the command's output schema, prints JSON or text, and maps a `DigestError` to its exit code. | Stricli types the flags; zod types the output (spec approach B). |
| Every output schema is in one map, `OUTPUTS` (`src/cli/outputs.ts`). `schema <name>` prints `z.toJSONSchema` of an entry; `schema` with no name lists the names; `schema --openapi` prints the oRPC contract as OpenAPI. | One place for the agent-facing shapes. |
| PR targets (`#123`, a PR URL) and `publish` / `pull` / `comments --publish` are plan 5. In plan 4, a PR target gives `BAD_INPUT` with a hint. | They need the backends. |
| `export` is plan 6. | It needs the UI bundle. |
| Commands that take other positional arguments (`resolve`, `note`, `mark`) take the digest as `--ref <ref>`. | A positional `[ref]` would be ambiguous. |
| Comment commands run in-process through `createRouterClient`; `wait` calls the running server; `serve` starts it with `ensureServer`. | Spec §7: only `wait` and `serve` need the server. |
| The command that starts the server is `[execPath, "server", "run"]` in the compiled binary and `[execPath, Bun.main, "server", "run"]` from source. | The same code works in both. |
| `fmt --questions-to-notes` adds each question as an agent note on the digest title block. | Plan 2 carry-forward. |
| `package.json` gets a `cli` script (`bun src/cli/index.ts`). The installed `diff-digest` still runs the old tool until plan 7. | Plan 7 does the cutover. |

## Tasks

1. **Command core.** `src/cli/output.ts` (`emit`, JSON/text printing, exit codes), `src/cli/outputs.ts` (output schemas), `src/cli/app.ts` (the route map), `src/cli/index.ts` (entry, usage exit code 2), `src/cli/context.ts` (the Stricli context: process, cwd, home), text-module types. Commands: `format`, `prompt`, `config [--init]`, `schema [name] [--openapi]`. Tests: run the CLI as a subprocess (`bun src/cli/index.ts …`) with a temp `DIFF_DIGEST_HOME`.
2. **Targets and the digest reference.** `src/cli/target.ts` (branch, commit, range, current branch; ported from `bin/diff-digest.mjs`), `src/cli/ref.ts` (`resolveDigest`: nothing, a target, `--id`, a `.md` path → `{ entry, target }`, registering the entry). Commands: `target`, `init`, `path`, `hunks`. Tests in a temp repo.
3. **Format commands.** `lint`, `check`, `fmt [--check] [--questions-to-notes]`. Exit 5 for lint errors, 6 for coverage gaps; `fmt --check` exits 5 when the file would change.
4. **Comment commands.** `comments [--status] [--markdown]` (the review Markdown, ported from `reviewMarkdown`), `resolve`, `note`, `mark`. In-process router client.
5. **Server commands.** `serve [ref] [--open]`, `wait [ref] [--timeout]`, `server run | status | stop | restart | logs`. Tests start and stop a real server in a temp home.
