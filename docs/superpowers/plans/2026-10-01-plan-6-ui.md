# Plan 6: The review UI (React 19.3)

**Goal:** The browser UI from spec §10, on React 19.3 and the plan 3 contract: the digest rendered from Markdown tokens with comments on each block, the code pane (Diff, After, Before) with line and range comments, the file tree with "Mark generated", the action buttons, the listener status, and the publish dialogs. It reaches feature parity with `ui/app.js`.

**Spec:** `docs/superpowers/specs/2026-09-30-typescript-rewrite-design.md` §10 (UI), §1 product rules (the UI renders CommonMark + GFM, as other viewers do), §11. Carry-forward tables at the end of the plan 1–5 files (plan 2: render from `marked` tokens, not from `parseBlocks`; map blocks to `cid`s by line; plan 3: one change can give two `comments` events; a queued click can expire; the HTML page is not behind the Host check).

**Execution:** the controller builds each task in the repo with `bun run verify` passing before each commit, then an Opus whole-plan review, one fix wave, and a re-review (user goal 2026-10-01). The UI gets a manual Playwright check.

## Global constraints

- Same as plans 1–5.
- New exact dependencies: `react`, `react-dom` 19.3.0; `@types/react`, `@types/react-dom` 19.3.0 (dev); `mermaid` 12.0.0; `highlight.js` 11.12.0.
- `src/app/**` imports only pure lib files (spec §3) and no Node or Bun API. A new lint override enforces this, and the `react-hooks` rules (`rules-of-hooks`, `exhaustive-deps`) are on for `src/app/**` (plan 1 carry-forward). Both make the rules stricter.
- `mermaid` loads with `await import("mermaid")` only when a digest has a diagram; `highlight.js` uses `lib/core` with about 12 registered languages.
- The UI never changes the DOM after React renders it, except the Mermaid SVG inside its own element.

## Rulings in this plan

| Ruling | Why |
|---|---|
| The server serves `src/app/index.html` through `Bun.serve({ routes: { "/d/:id/": page } })`, with `fetch` as the fallback for `/rpc` and `/health`. The page and its `/_bun/` assets are not behind the Host check; they carry no data. | Bun's HTML imports serve only through `routes`. |
| The UI renders the `src/lib/md.ts` Block tree and re-lexes only inline text with `marked.Lexer.lexInline` (`src/app/markdown/rich-inline.ts`). `ListItem` gains `ownText` and `checked`. Block ids come from `buildModel(body, lineOffset).blocks`, matched by file line; the payload gains `lineOffset`. | One block parser for the linter and the UI (plan 2 carry-forward). |
| `export` (one static HTML file) moves to plan 7, where the build makes the static bundle. | It needs a build step. |
| The UI fetches again on a `digest` or `comments` event, and drops a second event of the same type that arrives within 100 ms. | Plan 3 carry-forward (two events for one change). |
| The dialogs are a conditional overlay `div`, not `<dialog>`. A table row that takes comments is a real `<tr>` with its thread in the next row. | React owns the DOM (no imperative `showModal`). |
| The page loads no fonts or styles from a CDN. The highlight.js theme comes from the package (`@import` in `styles.css`). | Spec §2: nothing loads from a CDN. |
| The Publish dialog has "Publish even with lint errors" (`force`). An error toast shows the error's hint. | A digest with lint errors is refused (LINT_FAILED) and the hint names `--force`. |
| A dropped event stream retries every 2 s and fetches the digest and the comments again when it is back. | Events sent while offline are lost. |
| Unit tests cover the pure UI logic (token adapter, unified-diff parser, range selection, tree building); the components get a manual Playwright check. | Spec §13: no browser test dependency. |

## Tasks

1. **Serving and the app shell.** Dependencies, the `src/app/**` lint override, `src/app/index.html`, `main.tsx`, `api.ts` (digest id from the URL, typed client), `styles.css` (the tokens from `ui/styles.css`), the server route. The page shows the digest title and the meta chips.
2. **Digest rendering.** `src/app/markdown/` (token adapter, React renderer, Mermaid block, anchor spans), block ids by line. Test: the adapter.
3. **Comments.** Threads under blocks, the composer, delete, agent notes, other comments; live reload through `events` with the de-duplication.
4. **Code pane.** Diff, After, Before; the "unchanged" tag; highlighting; line and range comments (drag from `+`); the ⋯ menu with Mark generated. Tests: the diff parser and range selection.
5. **File tree, toolbar, and dialogs.** File tree; Apply and Review buttons; the listener status; the "Post comments" dialog (preview the review Markdown, choose backends, post); the "Publish" dialog (choose backends, dry-run preview, publish); toasts. Then the manual Playwright check against a real repo.
